## 口径（与模板第 9 行一一对应）

| 列 | 计算 |
|----|------|
| 期初数量 / 单价 / 金额 | 上一期期末数量 / 单价 / 金额 |
| 本期入库数量 | 采购(2) + 销售退回(5) + 盘盈(8) + 其他入库(9) + 组装单入库(12) + 拆卸单入库(14) + 加工单入库(17) |
| 本期入库单价 | 本期入库金额 / 本期入库数量 |
| 本期入库金额 | 上述入库单据的 `enter_cost` 合计 + 成本调整单(7) 的 `enter_cost` |
| 本期出库数量 | 采购退回(3) + 销售(4) + 盘亏(10) + 其他出库(11) + 组装单出库(13) + 拆卸单出库(15) + 加工单出库(16) |
| 本期出库单价 | (期初金额 + 本期入库金额) / (期初数量 + 本期入库数量)　← 移动平均，**不是**出库金额/出库数量 |
| 本期出库金额 | 上述出库单据的 `out_cost` 合计（单据实际成本） |
| 期末数量 | 期初 + 入库 − 出库 |
| 期末单价 | 期末金额 / 期末数量 |
| 期末金额 | 期初金额 + 入库金额 − 出库金额 |

## 关键设计

### 1. 快照粒度 = 商品 + 仓库

`fa_kuerp_stock_summary` 唯一键 `(period, goods_id, stores_id)`。页面「仓库」下拉默认 **全部仓库**，此时按商品合并成一行（与模板版式一致）；选具体仓库时按该仓库看。

### 2. 调拨单(6) 单独存 `transfer_*` 列

调拨是仓间移动：

- **全部仓库**合并时一进一出正好抵消，不计入本期收发（否则会虚增入库/出库）；
- **单个仓库**查看时计入该仓库的本期收发。

`StockSummary::mergeRows($rows, $merge)` 按 `$merge` 决定是否把 `transfer_*` 并入 `in_*` / `out_*`。库里的 `in_qty`/`out_qty` **不含**调拨。

### 3. 期末用「当前库存倒推」锚定

```
期末数量 = 商品库存余额表当前库存(该商品+仓库) − 本期结束后发生的收发
期初     = 期末 − 本期净收发
```

这样**最新一期的期末恒等于「商品库存余额表」**，不会因为历史日志的行数/成本缺失而漂移；首期（启用月）的差额自动落成期初（即系统启用期初）。实测：2026-09 期末 3,124,421 + 10 月净收发 3 = 库存表 3,124,428 ✓。

### 4. 未满月份期末留空

`is_complete = end <= time()`。未结束的月份里 `end_qty / end_price / end_money` 写 **NULL**，页面/导出都显示空白（不是 0），合计行同期留空并附「（月份未结束，期末留空）」提示。

月份判定以「月份」为准而不是「是否有行」，所以空数据的未来月份也返回 `is_complete=0`。

### 5. 缺快照自动补算

页面打开某月但该月没有快照时，`index()` 会现场跑一次 `build()`（仅限 `<= 当前月`），所以首次查看历史月不用先点【重新计算】。未来月份不建快照，返回空列表。

### 6. 移动平均单价

合并行的单价必须在合并后的数量/金额上重算（不能取某一仓库的单价），集中在控制器 `calcPrices()`。

## 已验证（curl + headless Chrome/CDP 实测 erp.licheng.test，测试数据已还原）

- 计算：2026-05/09/10 三个月分别 675/675/677 行；9 月（已结束）期末 3,124,421 与库存表 3,124,428 减去 10 月净收发 3 完全吻合；10 月（未结束）`end_*` 全为 NULL。
- 金额口径：临时插入一条 2026-09-15 的 +10 件 × 50 元采购日志并把库存成本 +500 → 9 月 `in_qty=10 / in_money=500 / in_price=50`、`out_price=0.2488`（= (0+500)/(2000+10)）、`end_money=500`、`end_price=0.2493`，且正确结转为 10 月期初（2006 / 500）。测后日志与库存已还原。
- 页面：合计栏（表格上方，进入即可见）、18 列表头、分页 100 条、未满月份期末列为空白、fixed 左右列行高 41px 与主表一致（1600/1200/900 三种宽度）。
- 单仓库：`stores_id=5` 返回 5 行、`stores_id=6` 全局 677 行；按物料编码 LIKE 过滤正常。
- 导出：9 月 xlsx 692 行 × 16 列，表头/数据/合计行/字段说明 13 行齐全；未来月份导出返回「该月份暂无数据」提示。
- 自动补算：删掉 2026-05 快照后直接请求 → 自动重建 675 行。
- 菜单：侧栏「资金 → 收发存汇总表」在「利润表」之后，链接宽高 230×46 正常。
- 定时任务：`php think kuerp:stock_summary --period=2026-09` 输出「675 行」，耗时 0.26s。

## 数据现状备注（本库）

- `fa_kuerp_goods_purchase_info.unit_price` 全为 0，采购入库成本主要靠 `fa_kuerp_goods_stock.cost_money`；本报表金额列以 `kuerp_goods_log` 的 `enter_cost` / `out_cost` 为准，与库存表成本同源。
- 组装单(12/13)、拆卸单(14/15) 的 `kuerp_goods_log` 行 `enter_cost`/`out_cost` 目前写 NULL（代码里被注释掉），所以这些单据在报表里**只有数量没有金额**；补金额属于单据侧改造，不在本次范围。
