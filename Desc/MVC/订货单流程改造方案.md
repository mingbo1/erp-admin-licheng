## Step 2 — MiniOrder Controller: confirm() 改为跳转模式

**文件**: `application/admin/controller/kuerp/MiniOrder.php`

**`confirm()` 方法改为**:

不再 POST 创建销货单，改为 GET 直接跳转到 `kuerp/goods_sales/add`：

```php
/**
 * 确认订单（跳转到销货单新增页面）
 */
public function confirm()
{
    $id = $this->request->param('ids/d');
    if (!$id) {
        $this->error(__('参数错误'));
    }

    $order = $this->model->with(['goods'])->find($id);
    if (!$order) {
        $this->error(__('订单不存在'));
    }
    if ($order->status !== 'pending_confirm') {
        $this->error(__('当前状态不可确认'));
    }

    // 跳转到销货单新增页面，预填订单数据
    $url = url('kuerp/goods_sales/add', ['order_id' => $id]);
    $this->success('跳转中...', $url);
}
```

**说明**: `url()` 生成绝对 URL，前端拿到后打开新页面或当前页跳转。后端会自动查 `kuerp_user_order` 和 `kuerp_user_orderinfo` 预填数据（GoodsSales.add 已支持 `$order_id` 参数）。

**检查点**:

- [ ]  `confirm()` 不再 POST 建销货单和检查库存
- [ ]  `confirm()` 校验 `status === 'pending_confirm'`
- [ ]  `confirm()` 调用 `url('kuerp/goods_sales/add', ['order_id' => $id])` 跳转
- [ ]  `confirm()` 返回 `$this->success('跳转中...', $url)`

## Step 5 — Collection Controller: 审核收款单时回调 mini_order

**文件**: `application/admin/controller/kuerp/Collection.php`

**位置**: `examine()` 方法内，销货单核销处理处（约第 816-817 行）

原始代码（审核收款单，更新销货单支付状态）：

```php
// 约第816行
Db::name('kuerp_goods_sales')->where(['purchase_code'=>$info_list_v['purchase_number']])
    ->update(['pay_money'=>$pay_money,'pay_status'=>$status]);
```

**在此之后增加回调**：

```php
// 更新销货单支付状态
Db::name('kuerp_goods_sales')->where(['purchase_code'=>$info_list_v['purchase_number']])
    ->update(['pay_money'=>$pay_money,'pay_status'=>$status]);

// == 新增: 销货单已付清 → 通知订货通订单改为已支付 ==
if ($status == 1) {
    $miniOrder = Db::name('kuerp_mini_order')
        ->where('sales_code', $info_list_v['purchase_number'])
        ->where('status', 'confirmed')
        ->find();
    if ($miniOrder) {
        Db::name('kuerp_mini_order')
            ->where('id', $miniOrder['id'])
            ->update([
                'status'     => 'paid',
                'updatetime' => time()
            ]);
    }
}
```

**回调时机说明**:

- `$status == 1` 表示销货单已全部付清（pay_status=1）
- `$info_list_v['purchase_number']` 是销货单号，对应 `kuerp_mini_order.sales_code`
- 加 `status='confirmed'` 条件避免重复回调已 paid 的订单
- 该方法在 `Db::startTrans()` 事务内，与收款审核在同一事务，安全可靠

**检查点**:

- [ ]  在 `kuerp_goods_sales` 的 `pay_status` 更新代码后增加回调
- [ ]  判断 `$status == 1`（全部付清才回调）
- [ ]  通过 `sales_code = purchase_number` 关联查询 `kuerp_mini_order`
- [ ]  增加 `status='confirmed'` 条件防重复更新
- [ ]  回调也在事务内（和原有 `Db::startTrans()` 一致）

## 完整状态流转图

```
用户下单
  → pending_confirm
      ↓ 操作员点击"确认" → 跳转 GoodsSales.add(order_id=X) → 操作员修改提交
      ↓
      confirmed (订单已有 sales_code)
      ↓ 销货单审核 → 收款单审核（全部付清）
      ↓
      paid (← 新增)
      ↓ 操作员点击"发货"
      shipped
      ↓ 用户签收
      received
      ↓
      completed
    
      任何阶段可取消 → cancelled
      用户退货 → returned
```

## 数据关联路径

```
收款审核回调:
  Collection.examine()
    → $info_list_v['purchase_number']  (销货单号)
    → kuerp_goods_sales.purchase_code  (匹配)
    → kuerp_mini_order.sales_code      (匹配)
    → update status = 'paid'

不需要新增任何数据库字段。
```
