# 外协加工单 开发方案（修订版）

## 一、需求概述

外协加工：将原材料/半成品发给第三方加工商（**供应商**），加工完成后收回成品，加工商收取加工费。

### 核心流程

```
1. 创建加工单 → 选加工商(供应商)、选原材料(出库)、选成品(入库)
2. 审核加工单 → 原材料库存扣除（库存-），不涉及费用
3. 外协入库    → 成品入库（库存+），手动输入成品单位成本，录入加工费（关联财务）
```

### 关键澄清

| 问题 | 结论 |
|------|------|
| 加工商身份 | **供应商**（`fa_kuerp_suppliers`），不是客户 |
| 仓库选择 | 每行明细独立选仓库，同商品不同仓库=加行 |
| 出库费用 | **无**，审核出库不涉及任何费用 |
| 原材料成本 | 创建时自动带出当前库存单位成本（用于出库记账 goods_log.out_cost） |
| 成品成本 | **手动输入**单位成本，自动算总价（= 单价 × 数量） |
| 加工费 | 入库时手动录入，关联财务支出 |

| `row[remark][]` | `remark` | 备注 |
| `row[batch][]` | `batch` | 批次 |
| `row[batch_id][]` | `batch_id` | 批次ID |
| `row[manufacture][]` | `manufacture` | 生产日期 |
| `row[guarantee][]` | `guarantee` | 保质期 |
| `row[validity][]` | `validity` | 过期时间 |

Controller 中 `add()` 保存时的映射：
```php
'unit_cost'  => $params['unit_price'][$k],   // 表单→DB
'cost_money' => $params['all_money'][$k],    // 表单→DB
```

Controller 中 `edit()` 回显时的反向映射（在 PHP 侧组装 `$purchase_info` 时）：
```php
$purchase_info[$k]['unit_price'] = $purchase_info[$k]['unit_cost']; // DB→表单
$purchase_info[$k]['all_money']  = $purchase_info[$k]['cost_money'];
```

## 四、控制器方法设计

### 4.1 方法清单

| 方法 | 说明 |
|------|------|
| `_initialize()` | 绑定model, 加载供应商/仓库/商品列表 |
| `index()` | 列表查询，关联供应商信息 |
| `add()` | 新增加工单（选供应商+原材料+成品） |
| `edit($ids)` | 编辑加工单（仅未审核可编辑） |
| `del($ids)` | 删除（未审核可删） |
| `examine($ids, $examine=1)` | 审核(出库扣库存) / 反审核(退回库存) |
| `processIn()` | **外协入库**: 手动输入单价+加工费 |

### 4.2 examine() 审核/出库

```
审核(examine=1):
1. 检查结账时间
2. 查询 process_info 中 type=1 的原材料明细
3. 遍历每条原材料:
   a. 检查库存是否充足(stock >= basic_number) → 不足则报错
   b. 扣减库存数量:
      - fa_kuerp_goods_stock.stock       -= basic_number
      - fa_kuerp_goods_stock.cost_money  -= cost_money  (仓库库存成本减少)
      - fa_kuerp_goods.inventory         -= basic_number
   c. 记录 fa_kuerp_goods_log: business_type=14 (外协出库)
      out_number  = number
      out_basics  = basic_number
      out_unit    = unit_cost  (创建时自动带出的库存成本)
      out_cost    = cost_money
   d. 批次/序列号跟踪 (business_type=14)
4. 更新主表: examine_status=1, in_status=0
5. 事务提交

反审核(examine=2):
1. 检查 in_status=0 (有任何入库记录则报错，提示"请先处理入库记录")
2. 反向恢复:
   - fa_kuerp_goods_stock.stock       += basic_number
   - fa_kuerp_goods_stock.cost_money  += cost_money
   - fa_kuerp_goods.inventory         += basic_number
3. 删除 goods_log/batch_log/serial_log (business_type=14)
4. 恢复序列号状态 (store_status 改回 1=在库)
5. 更新主表: examine_status=0
```

### 4.3 processIn() 外协入库

```
POST参数:
  process_id:          加工单ID
  in_goods[]:          入库成品 [{info_id, in_number, unit_cost}]
  batch_data[]:        批次信息 [{info_id, batch, manufacture, guarantee, validity}]
  serial_data[]:       序列号 [{info_id, period}]
  account_id:          结算账户
  expend_type_id:      支出类别
  total_process_fee:   本次加工费合计
  fee_time:            费用日期

入库粒度: 按成品行独立入库
  例: 成品A(计划5个) + 成品B(计划3个)
  → 可以A入3个、B入0个（A部分入库,B未入库）
  → 可以A入5个、B入3个（全部入库）
  → 不能A入0个、B入0个（至少入库一个成品）

流程:
1. 验证 examine_status=1 (必须已审核)
2. 验证至少有一条成品 in_number > 0
3. 查询 type=2 成品明细
4. 遍历每条入库成品 (in_number > 0 的):
   a. 验证 in_number > 0 且 <= (number - in_number)
   b. 计算 cost_money = unit_cost × in_number (后端必须校验)
   c. 增加库存:
      - fa_kuerp_goods_stock.stock       += in_number × basic_number (对应仓库)
      - fa_kuerp_goods_stock.cost_money  += cost_money
      - fa_kuerp_goods.inventory         += in_number × basic_number
   d. 记录 fa_kuerp_goods_log: business_type=15 (外协入库)
      enter_number = in_number
      enter_basics = in_number × basic_number
      enter_unit   = unit_cost
      enter_cost   = cost_money
   e. 更新 process_info: in_number += in_number, unit_cost, cost_money
   f. 批次处理 (参照组装件入库逻辑):
      - 新批次: insert fa_kuerp_goods_batch + fa_kuerp_goods_batch_stock
      - 已有批次: update fa_kuerp_goods_batch_stock.stock
      - 记录 fa_kuerp_goods_batch_log (business_type=15)
   g. 序列号处理 (参照组装件入库逻辑):
      - 新序列号: insert fa_kuerp_goods_serial (status=15, store_status=1)
      - 记录 fa_kuerp_goods_serial_log (business_type=15)
5. 记录加工费:
   a. fa_kuerp_process_fee: 加工费 + 供应商 + 账户 + 支出类别
   b. fa_kuerp_accounts_log: business_type=7, expenditure=total_process_fee
   c. fa_kuerp_accounts.balance -= total_process_fee
   d. fa_kuerp_cost: business_type=3, money=total_process_fee
6. 更新主表:
   - in_number += 本次入库总数
   - total_process_fee += total_process_fee
   - in_status: 判断每条成品 (in_number==number) → 全满=2/部分=1
   - in_time = now
7. 事务提交
```

### 4.4 状态流转规则

```
[创建] → examine_status=0, in_status=0
   ↓ 审核
[已审核] → examine_status=1, in_status=0
   ↓ 外协入库(可多次)
[部分入库] → examine_status=1, in_status=1
   ↓ 外协入库(最后一次)
[全部入库] → examine_status=1, in_status=2

编辑: 仅 examine_status=0 可编辑
删除: 仅 examine_status=0 可删除
反审核: 仅 in_status=0 可反审核
```

## 七、成本与财务逻辑

### 7.1 成本计算

```
创建加工单时(type=1 原材料):
  自动从当前库存获取 unit_cost(移动平均成本), 只读显示
  cost_money = unit_cost × basic_number (自动计算)

出库(审核):
  goods_log.out_unit = process_info.unit_cost  (自动带出的库存成本)
  goods_log.out_cost = process_info.cost_money
  goods_stock.cost_money -= cost_money  (仓库库存成本减少)

入库(type=2 成品):
  手动输入 unit_cost → 后端计算 cost_money = unit_cost × in_number
  goods_log.enter_unit = unit_cost
  goods_log.enter_cost = cost_money
  goods_stock.cost_money += cost_money  (成品仓库成本增加)
  与成品原有库存合并: 新移动平均 = (原库存×原成本 + 本次入库成本) / (原库存+本次数量)
```

### 7.2 财务记录

| 操作 | 财务表 | 记录 |
|------|--------|------|
| 入库加工费 | `fa_kuerp_process_fee` | 加工费明细 |
| 入库加工费 | `fa_kuerp_accounts_log` | 账户流水(business_type=7), expenditure=加工费 |
| 入库加工费 | `fa_kuerp_accounts` | 结算账户 balance -= 加工费 |
| 入库加工费 | `fa_kuerp_cost` | 费用表(business_type=3), money=加工费 |

**不涉及**: 应付账款(`accounts_copewith`)、供应商应收应付余额
