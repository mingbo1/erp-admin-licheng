# 微信小程序端 — MVP

## 功能说明
前端 uni-app 项目放在 `addons/kuerp/uniapp/` 目录下，后端 API 写在 `addons/kuerp/` 中。
微信小程序用户端（uni-app + Vue 3），提供商品浏览、购物车、下单功能。用户下单后由后台管理员确认，确认时生成销货单进入完整审核流程。

```
用户浏览下单 → 后台确认(生成销货单草稿) → 销货单审核(扣库存+算成本)
 → 对单(即确认付款) → 发货 → 用户确认收货 → 完成
```

发货支持两种配送方式：
- **物流配送**：填写快递公司和快递单号，用户端可查询物流轨迹
- **专业配送**：填写配送员/承运方和联系电话，后台发货即完成，无轨迹

一个订单只需一次发货（整单发），物流单号关联到订单级别。

    `user_id` int(11) NOT NULL DEFAULT '0' COMMENT '关联fa_user.id',
    `customer_id` int(11) NOT NULL DEFAULT '0' COMMENT '关联fa_kuerp_customers.id(登录时自动创建)',
    `openid` varchar(100) NOT NULL COMMENT '微信openid',
    `unionid` varchar(100) NOT NULL DEFAULT '' COMMENT '微信unionid(跨平台统一标识)',
    `apptype` varchar(20) NOT NULL DEFAULT 'miniapp' COMMENT '来源: miniapp=小程序, mp=公众号',
    `nickname` varchar(100) NOT NULL DEFAULT '' COMMENT '微信昵称',
    `avatar` varchar(500) NOT NULL DEFAULT '' COMMENT '微信头像',
    `mobile` varchar(20) NOT NULL DEFAULT '' COMMENT '手机号',
    `session_key` varchar(100) NOT NULL DEFAULT '' COMMENT '小程序session_key(仅miniapp)',
    `status` varchar(20) NOT NULL DEFAULT 'normal',
    `createdtime` bigint(16) NOT NULL DEFAULT '0',
    `updatetime` bigint(16) NOT NULL DEFAULT '0',

## 订单状态机

### 完整状态定义

```text
pending_confirm  ─→ cancelled            (用户/管理员取消)
       │
       ▼
confirmed        ─→ cancelled            (管理员取消,需回退库存+作废销货单)
       │
       ▼
shipped                                (管理员发货,整单发货)
       │
       ▼
  received      ─→ returned            (用户确认收货 / 售后退货)
       │
       ▼
   completed                            (订单完成)
```

| 状态 | 含义 | 谁操作 | 触发条件 |
|------|------|--------|---------|
| `pending_confirm` | 待管理员确认 | 系统 | 用户提交后自动进入 |
| `confirmed` | 已确认(可发货) | 管理员 | 确认订单→生成销货单草稿→审核→对单(即完成确认付款)后状态 |
| `shipped` | 已发货 | 管理员 | 后台发货操作后进入 |
| `received` | 已签收 | 用户 | 用户在端上确认收货 |
| `completed` | 已完成 | 系统 | 确认收货后自动完成 |
| `cancelled` | 已取消 | 用户/管理员 | 取消操作 |
| `returned` | 已退货 | 管理员 | 后台手动标记 |

## 下单到完成完整流程

```text
┌─────────────────────────────────────────────────────────┐
│                   用户端                                  │
│                                                          │
│  1. 微信登录 → 自动创建客户(fa_kuerp_customers)          │
│     并关联 customer_id                                   │
│                                                          │
│  2. 浏览商品列表(按分类筛选,支持搜索名称/编码,按销量/价格排序)  │
│     → 商品详情(主图+图集+详情content+选择属性+单位,价格根据 customerlevel_id 自动匹配)      │
│                                                          │
│  3. 加入购物车(支持属性和单位)                            │
│     → 购物车列表(修改数量/删除)                           │
│                                                          │
│  4. 结算 → 选择收货地址(fa_kuerp_customers_user)         │
│     → 填写备注 → 提交订单                                 │
│                                                          │
│  订单状态: pending_confirm                                │
└──────────────┬──────────────────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────────────┐
│         后台管理 - 订货通 → 订货单管理                    │
│                                                          │
│  1. 待确认订单列表 → 查看详情(商品+地址)                  │
│  2. 确认订单:                                            │
│     a. 选择发货仓库                                       │
│     b. 自动生成草稿销货单(kuerp_goods_sales)             │
│     c. 商品明细由订单商品明细转换                         │
│     d. 订单状态 → confirmed                              │
│     e. 记录 sales_code                                    │
│                                                          │
│  ── 后续操作在进销存→销货→销货单模块进行 ──              │
│  3. 销货单审核 → 扣减库存+计算成本                        │
│  4. 对单 → 标记对账状态(即完成确认付款)                   │
│                                                          │
│  ── 返回订货通→订货单管理继续 ──                          │
│  5. 发货(整单发货,物流关联到订单,confirmed状态可发货):   │
│     a. 物流配送: 快递公司+单号 → 可查物流轨迹            │
│     b. 专业配送: 配送员+电话 → 发货即完成               │
│     c. 订单状态 → shipped                                 │
└──────────────┬──────────────────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────────────┐
│                   用户端                                  │
│  订单状态: 已发货                                             │
│  查看物流: 快递公司+单号 / 配送员+电话                     │
│  确认收货 → received → completed                          │
└─────────────────────────────────────────────────────────┘
```

## 商品详情数据说明

### 商品字段说明

`fa_kuerp_goods` 表已有字段直接使用，无需新增：

| 字段 | 用途 | 前端展示 |
|------|------|---------|
| `goods_image` | 商品主图 | 详情页顶部主图 |
| `goods_images` | 商品图集(text,多张图片) | 主图切换轮播 |
| `content` | 商品详情(text,富文本HTML) | 详情页底部富文本区域 |
| `status=1` | 上架状态 | 只展示status=1的商品 |

### 价格展示逻辑

根据当前用户的 `customerlevel_id` 自动匹配对应价格等级：

```text
customerlevel_id = 1 → market_sell_price（零售价，默认）
customerlevel_id = 2 → wholesale_price（批发价）
customerlevel_id = 3 → vip_price（VIP价）
```

- 新注册用户 `customerlevel_id` 默认为 1，展示零售价
- 后台修改客户等级后，用户端价格自动变化
- 购物车、结算、订单金额均按此规则计算

### 库存为0处理

- 库存为0的商品在列表和详情页均正常展示，显示"已售罄"标记
- 加入购物车按钮禁用，不可购买
- 使用 `fa_kuerp_goods_stock` 表查询实时库存

### 订单编号规则

使用 `kuerp_prefix` 表的编号规则：

- 在 `kuerp_prefix` 中配置编号前缀（如 `DD`）、是否启用年月日、流水号长度等
- 生成示例：`DD202605180001`
- 统一走 `Goods::getCodes` 方法生成

## 小程序用户关联客户逻辑

用户首次微信登录时自动执行：

```
1. 微信登录(code) → 获取 openid + 用户信息
2. 检查 fa_kuerp_mini_user 是否存在(openid+apptype)
3. 不存在则:
   a. 在 fa_user 创建记录(type='wxapp')
   b. 在 fa_kuerp_customers 创建客户:
      - customer_name = 微信昵称
      - customerlevel_id = 1(普通等级)
      - status = 1
   c. 在 fa_kuerp_mini_user 创建记录:
      - customer_id = 新创建的客户ID
4. 返回登录态 token
```

## 后台"确认付款"说明（对单即付款）

沿用现有进销存系统的对单逻辑，不新建"确认付款"功能：

- 订单 `confirmed` 后，管理员在 **进销存 → 销货 → 销货单** 模块中找到对应的销货单
- 销货单审核通过后，执行**对单**操作，即视为完成确认付款
- 对单后订单状态仍为 `confirmed`（已确认），可进行发货操作
- 无需单独开发 "确认付款" 按钮和功能

## 业务规则

### 用户与登录
1. 用户必须先微信登录才能使用购物车和下单功能
2. 登录后保留登录态，token 过期自动刷新
3. 首次登录自动创建 `fa_user` + `fa_kuerp_customers` + `fa_kuerp_mini_user`（含 `customer_id` 关联）

### 购物车
4. 支持多属性和多单位：`attr_ids` + `goods_unit` 区分不同规格
5. 购物车商品数量不能超过商品库存上限
6. 加入购物车不存价格快照，结算时实时读取商品最新价格

### 商品展示
7. 商品列表只展示 `status=1`（上架）的商品
8. 库存为0的商品展示"已售罄"标记，不可购买（加入购物车按钮禁用）
9. 商品列表支持按名称/编码搜索
10. 商品列表支持按销量/价格排序
11. 价格展示根据 `customerlevel_id` 自动匹配：`market_sell_price=零售价`（默认）、`wholesale_price=批发价`、`vip_price=VIP价`

### 下单
12. **收货地址为必填项**：从 `fa_kuerp_customers_user` 中选择或新增
13. 下单时锁定购物车中对应商品，提交成功后清空已购购物车项
14. 需做幂等处理，防止重复下单（前端防重复点击 + 后端唯一索引校验）
15. 订单金额计算：商品单价取结算时的最新价格（根据用户 customerlevel_id 自动匹配对应价格等级）
16. 订单编号使用 `kuerp_prefix` 表的编号规则（前缀+年月日+流水号）

### 订单确认（后台）
17. 确认订单时自动生成草稿状态的 `kuerp_goods_sales`（销货单）
18. 销货单的客户取 `mini_order.customer_id` 对应客户
19. 确认时管理员选择**发货仓库**
20. 如果库存不足，提示具体商品名称和差额数量，不允许确认

### 确认付款（对单即付款）
21. 不专门开发"确认付款"功能，沿用现有销货单 → 对单逻辑
22. 管理员在进销存销货单模块完成审核 + 对单操作
23. 对单后 `payment_time` 记录对单时间，订单状态保持 `confirmed`（可发货）

### 销货审核（走进销存完整流程）
24. 销货单在 `examine` 审核时执行：扣减库存 + 计算销售成本
25. 审核不通过反审核后，库存自动回退
26. 审核通过后可进行对单操作

### 发货
27. 已确认（`confirmed`）的订单才能发货（对单操作完成后即可发货）
28. **整单发货**，订单内所有商品一次发完，不支持部分发货
29. 物流只关联到订单级别（不关联到具体商品）
30. **物流配送**：填写快递公司 + 快递单号，用户端可查询物流轨迹（对接快递100/快递鸟等第三方接口）
31. **专业配送**：填写配送员/承运方名称 + 联系电话，管理员点击发货即完成，无物流轨迹
32. 发货后订单状态 → `shipped`

### 收货/完成
33. 用户确认收货 → `received` → 系统自动 `completed`
34. 售后退货走线下流程，后台手动标记 `returned`

### 取消
35. `pending_confirm` 状态：用户和管理员均可取消
36. `confirmed` 及以上状态：仅管理员可取消
37. 取消已确认的订单：回退库存 + 写入库存流水 + 关联销货单作废
38. 已取消的订单不可再次确认
