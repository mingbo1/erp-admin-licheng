# 销货对账（客户对账单）· 需求规格（2026-10-27 修订）

> 参与角色：销售（发起 / 导出 / 与客户线下确认）、财务（一审 / 开票 / 撤销）、
> **主管或领导（二审）**、管理层（查看）。本文是开发依据；实现细节以代码与迁移文件为准。
>
> **已确认**：栏目名「销货对账」；一张对账单可开**多张发票**；对账需要**二审（主管/领导）**；
> **销货退货单参与冲减**；版式按 `资料/财务功能/对账模板.xls`。
>
> 已有近似功能说明：`kuerp/customers_recon`（菜单「客户对账单」，资金组）目前是
> **应收账款余额表**（期初余额 + 销售/收款流水 + 小计 + 余额），没有单据实体、没有状态流转。
> 本需求是**新的单据型对账**，落在销货组下的新栏目「销货对账」，两者并存、互不覆盖。

## 一、总体流程

```
                销售 / 财务                                            财务 → 主管/领导
┌──────────────────────────────────┐
│ 1. 销货对账明细（工作台）          │
│    按 日期/客户/销售员/出库/对账/   │
│    开票/收款 筛选未对账单据明细     │
│    （含销货单与销货退货单，退货为负）│
│ 2. 勾选（不勾=全部筛选结果）        │
│ 3. [生成对账单] → 按客户拆分建单    │──→ 跳转「销货对账」列表
└──────────────────────────────────┘
                                              │
                    4. 详情页（按模板版式）/ 打印 / 导出 xlsx（客户+时间段）
                                              │
                    5. 财务把对账单发给销售与客户线下确认
                                              │
                ┌─────────────── 确认无误 ────┴──── 有异议 ─────────────┐
                ↓                                                        ↓
      [一审通过] recon_status=1（待二审）                      [撤销对账] recon_status=0
      锁定所含单据（禁止编辑/删除/反审核）                       解除锁定
                ↓                                                        ↓
      [二审通过] recon_status=2（已对账）                       调整单据（保留操作记录）
                ↓                                                        ↓
      [新增发票] ×N（可多张，金额累计）                          重新审核单据
      invoice_status 0→1(部分)→2(已开票)                              ↓
      每张发票上传文件+号码+金额+日期，                              [刷新明细]
      同步写回 kuerp_sales_invoicing                                   ↓
                ↓                                              重新一审 → 二审
      客户付款 → 收款单核销 → pay_status 自动派生
      （对账单显示 未收款 / 部分收款 / 已收款）
```

**核心原则**：对账单是**销货单与销货退货单的聚合快照**。单据是业务事实，对账单是
"这一期与这个客户核对了哪几张单、净额多少钱、开到票没、收到钱没"。

## 二、关键口径（已确认）

| 项 | 口径 |
|---|---|
| 对账来源 | **销货单 `kuerp_goods_sales` + 销货退货单 `kuerp_goods_sales_exchange`（均已审核）** 的明细行 |
| 退货处理 | **退货单作为负数行冲减**：数量、金额、客户费用全部取负 |
| 组织方式 | **客户 + 对账期间**；一次生成可跨多个客户，**按客户拆分**成多张对账单（一客户一张） |
| 纳入粒度 | **整张单据纳入**；在工作台勾选任意一行 = 该单据整单纳入（绝不部分对账） |
| 一张单据 | 同时只能属于**一张**对账单（任意状态）；释放须删除对账单或撤销后移出 |
| 销货合计金额 | **净额** = Σ销货单 `real_money` − Σ退货单 `real_money`（优惠后价税合计） |
| 客户费用 | **净额** = Σ销货单 `customers_money` − Σ退货单 `customers_money`（单据级字段） |
| 总金额 | `销货合计金额 + 客户费用`（与销货单 `need_money` 口径一致） |
| **单据应收总额** | **`real_money + customers_money`** —— 全系统唯一口径：欠款、核销封顶、收款判满、对账单总金额都用它 |
| 已付款 | **自动派生**：`已收 = Σ销货单 pay_money − Σ退货单 retreat_money`，对账单不手工标记 |
| 已开票 | 对账单上手工动作（上传发票），**支持多张发票**；按累计开票金额派生 未开票/部分开票/已开票，并**同步写回** `fa_kuerp_sales_invoicing` |
| 已对账 | **二审制**：财务一审 → **主管/领导二审**，二审通过才算"已对账"并回写单据 |
| 起止日期 | 以单据 `purchase_time` 落在对账期间内为准 |
| 公司抬头 | `fa_kuerp_sets.company_name`（当前：浙江大雁电驱技术有限公司） |

## 三、状态机

### 3.1 对账单 `fa_kuerp_sales_recon`

| 字段 | 取值 | 说明 |
|---|---|---|
| `recon_status` | 0 待对账 / 1 待二审 / 2 已对账 | 一审 → 二审；二审可驳回退回 0；可撤销 |
| `invoice_status` | 0 未开票 / 1 部分开票 / 2 已开票 | 按累计开票金额派生（见 5.6） |
| `pay_status` | 0 未收款 / 1 部分收款 / 2 已收款 | **派生**，不落手工值（冗余存一份便于排序） |
| `reject_reason` | varchar(255) | 二审驳回原因 |

列表「业务状态」优先级：`已驳回·待重提`（0 + 有原因）→ `待对账`（0）→ `待二审`（1）→
`已对账·待开票`（2 + 未开票）→ `部分开票` → `已开票·待收款/部分收款` → `已完成`（已收款）。

### 3.2 操作可用性

| 操作 | 允许条件 | 执行角色 |
|---|---|---|
| 编辑（增删单据 / 刷新明细 / 改备注） | recon_status=0 | 销售 |
| 删除 | recon_status=0 且 invoice_status=0 且 pay_status=0 | 销售 |
| 一审通过 | recon_status=0 | 财务 |
| 二审通过 | recon_status=1 | **主管/领导** |
| 二审驳回（必填原因） | recon_status=1 | **主管/领导** |
| 撤销对账 | recon_status∈{1,2} 且 invoice_status=0 且 pay_status=0 | 财务 |
| 新增发票 | recon_status=2 且 invoice_status≠2 | 财务 |
| 删除发票 | recon_status=2 且 pay_status=0 | 财务 |
| 去收款 | recon_status=2 且 pay_status≠2 | 财务/销售 |
| 导出 / 打印 / 详情 | 始终 | 全部 |

### 3.3 锁定规则

- `recon_status ≠ 0`（一审通过起）即**锁定**所含单据：禁止编辑 / 删除 / 反审核 / 反对单。
- 二审驳回或撤销对账 → 回到 0 → 解锁。
- 锁定校验落在 `GoodsSales::edit()/del()/examine()` 与 `GoodsSalesExchange::edit()/del()/examine()`
  的反审核分支，提示「该单据已进入对账，请先撤销对账后再修改」。

### 4.2 `fa_kuerp_sales_recon_doc` 单据级快照（新增）

> 客户费用、总金额、物流单号、出库状态都是**单据级**，单独成表，商品行挂在它下面。
> 这样模板里"客户承担费用/总金额只在该单据首行显示"能直接落库。

`id / recon_id / doc_type('1'销货,'2'退货) / doc_id / doc_code / doc_time(销售日期) /
customers_money / real_money(销货合计) / total_amount(总金额) / express_no(物流单号) /
out_status(0未出库/1部分/2已出/退货为NULL) / pay_money(销货已收/退货已退) / sort / createtime`

唯一键 `(recon_id, doc_type, doc_id)`；索引 `recon_id`。

### 4.3 `fa_kuerp_sales_recon_info` 商品行快照

`id / recon_id / recon_doc_id / doc_type / doc_id /
goods_code / goods_name / specification(型号) / vendor_name(规格2/厂商) / packaging(规格3/封装) /
goods_attr / attr_name / unit_id / unit_name / number(退货为负) / basic_nmber /
unit_price(未税单价) / tax_included(含税单价) / tax_rate(税点%) / tax_money / all_money /
money_tax_price / line_amount(行销货合计，退货为负) / purchase_order_id(关联销售订单号) /
remark / createtime`

- `line_amount` = 行价税合计；单据级优惠按行金额比例分摊，末行吃掉分差，保证 Σ`line_amount` = 单据 `real_money`。
- 索引 `recon_id`、`recon_doc_id`、`goods_code`。

### 4.4 `fa_kuerp_sales_recon_invoice` 发票（多张）

`id / recon_id / enclosure_id / invoice_no / invoice_amount / invoice_date / upload_date / admin_id / createtime / updatetime`

服务端校验同一对账单内发票号不重复。

### 4.5 `fa_kuerp_sales_recon_log` 操作日志

`id / recon_id / action / note / admin_id / createtime`

记录：创建 / 编辑 / 刷新明细 / 一审通过 / 二审通过 / 二审驳回 / 撤销对账 / 新增发票 / 删除发票 / 删除 / 导出。

| 表 | 改动 | 用途 |

| `fa_kuerp_goods_sales` | + `recon_id int DEFAULT 0`、`recon_code varchar(50)`、`recon_status enum('0','1','2') DEFAULT '0'` | 归属 / 销售端状态 / 锁定 |

## 五、页面与功能

### 5.1 销货对账明细（工作台）

**菜单**：销货 → 销货对账明细，路由 `kuerp/sales_recon/items`

**顶部筛选**：日期范围（默认本月）、客户、销售人员、单据类型（全部/销货单/退货单）、
是否已出库、是否已对账、是否已开票、是否已付款。

**数据范围**：`examine_status=1` 且 `recon_id=0` 的销货单/退货单明细；已结账期间排除。

**列**：单据日期 / 单据编号 / 单据类型 / 客户 / 销售人员 / 商品名称 / 型号规格 /
单位 / 数量（退货为负） / 含税单价 / 未税单价 / 税点 / 销货合计金额（退货为负） / 客户承担费用 /
总金额 / 关联销售单号 / 备注 / 物流单号 / 是否已出库 / 是否已对账 / 是否已开票 / 是否已付款。

- 客户承担费用、总金额、物流单号**只在该单据首行显示**（与模板一致），其余行留空。
- 退货单的"是否已出库"显示 `—`。
- 退货单的"是否已付款"取 `retreat_status`。

**底部合计**：销货合计金额总计、客户费用总计、总金额总计（均为**净额**）。

> ⚠️ `real_money` / `preferential_money` / `customers_money` 在明细表里是**单据级重复值**，
> 合计必须按**单据去重**后累加，不能直接 SUM 明细表。

**工具栏 [生成对账单]**：

1. 有勾选 → 取勾选行所在单据；无勾选 → 取当前筛选结果的全部单据。
2. 后端按 `customers_id` 分组，每组一张对账单（`KHDZ`），期间取筛选日期范围。
3. 事务内：主表 → 单据快照 → 商品行快照 → 回写单据 `recon_id/recon_code/recon_status='0'` → 日志。
4. 提示"已生成 N 张对账单"，跳转 `kuerp/sales_recon/index`。
5. 并发守卫：纳入前再校验 `recon_id=0`。

### 5.2 销货对账（对账单列表）

已开票金额 / 已收金额 / 业务状态 / 开票状态 / 收款状态 / 制单人 / 一审人 / 二审人 / 操作。

### 5.4 导出 Excel

- 直接以模板为蓝本（`资料/财务功能/对账模板.xls` 的 15 列与版式），`\PhpOffice\PhpSpreadsheet` 生成 `.xlsx`。
- 文件名：`{首个客户名称}{period_start}-{period_end}.xlsx`，多选导出时只取**首个客户名称**。
- 表头合并、本期合计行、往期各月未付款行、总未付款行、页脚声明与模板一致。
- 金额/数量按 `price_decimal` / `number_decimal`；单号一律文本格式。

### 5.5 一审 / 二审 / 驳回 / 撤销

**一审通过**：校验 `recon_status=0`、明细非空、源单据仍存在且已审核 →
`recon_status=1 / examine_id / examine_time`，清空 `reject_reason` → 回写单据 `recon_status='1'`（锁定）→ 日志。

**二审通过**（主管/领导）：校验 `recon_status=1` →
`recon_status=2 / second_examine_id / second_examine_time` → 回写单据 `recon_status='2'` → 日志。

**二审驳回**（主管/领导）：校验 `recon_status=1`、原因非空 →
`recon_status=0 / reject_reason`，清一二审人 → 回写单据 `recon_status='0'`（解锁）→ 日志。

**撤销对账**（财务）：校验 `recon_status∈{1,2}`、未开票、未收款 → 回 0、清审核人 → 解锁 → 日志。

**异议闭环**：撤销/驳回 → 改单据（`goods_sales_log` 留痕）→ 重新审核 →「刷新明细」→ 重新一审 → 二审。

### 5.6 开票（支持多张）

**应开票金额** = 销货合计金额**净额**（Σ销货 `real_money` − Σ退货 `real_money`），客户费用不开票。
**剩余可开票** = 应开票金额 − 已开票金额合计。

**新增一张发票**：

1. 校验 `recon_status=2`、`invoice_status≠2`、金额 > 0、≤ 剩余可开票；
2. 附件 `enclosure_log(type=12, order_id=recon_id)`；
3. 插 `sales_recon_invoice`（发票号唯一）；
4. 重算 `invoice_amount` 与 `invoice_status`（0 / 1 部分 / 2 已开）；
5. 同步写回开票台账（见下）；
6. 日志。

**删除一张发票**：`pay_status=0` 才允许 → 删附件关系与发票行 → 用剩余发票重算 → 台账全量重算 → 日志。

**台账写回规则（幂等全量重算）**：

```
待分摊 = Σ 本对账单剩余发票金额
按 doc_time, doc_code 升序取所含【销货单】（退货单不参与分摊）:
    应开票 = goods_sales.real_money
    本次 = min(应开票, max(待分摊, 0))
    待分摊 -= 本次
    更新 kuerp_sales_invoicing(bill_code=销货单号, recon_id=本单):
        pay_money = 本次, give_money = 应开票 - 本次,
        invoice_status = (give_money<=0 ? 1 : 0)
```

- 若某销货单在「销货开票管理」被**单独手工开过票**（`invoice_status=1 且 recon_id=0`）→ 跳过并告警。
- 退货单的红字发票不在本期写回范围（见待确认 1），但计入对账单净额。

### 5.7 收款与"已付款"派生

```
已收金额 = Σ销货单 goods_sales.pay_money − Σ退货单 goods_sales_exchange.retreat_money
应收总额 = Σ(销货 real_money + customers_money) − Σ(退货 real_money + customers_money)
pay_status = 已收<=0 ? 0 : 已收>=应收 ? 2 : 1
```

- 实时计算，同时冗余写回主表 `pay_money/pay_status` 供排序。
- 「去收款」跳 `kuerp/collection/add`，带入客户与对账单号到备注。

### 5.8 销售端状态回显

`kuerp/goods_sales` 与 `kuerp/goods_sales_exchange` 列表新增：
**对账状态**（`recon_status` + 对账单号）、**开票状态**（`kuerp_sales_invoicing.invoice_status`）；收款状态列已有。
筛选栏同步加这两项；详情/打印页信息区加「对账单号」。

### 5.9 收款口径统一（对现有收款/核销的存量改造）

**目标**：销货单应收总额全系统统一为 **`real_money + customers_money`**。

**现状问题**：

| 位置 | 现用基数 | 结论 |
|---|---|---|
| 销货单欠款 `arrears`（`goods_sales.js`） | `real_money + customers_money - 已收` | ✅ |
| `GoodsSales::examine()` 写 `writeoff_source.price` | `real_money` | ❌ 与 `write_off=arrears` 不同基数 |
| `GoodsSalesExchange::examine()` 写 `writeoff_source.price` | `-real_money` | ❌ 同上 |
| `Collection::examine()` 判满 | `real_money` | ❌ 不含客户费用 |
| `Writeoff::examine()` 判满 | `money_tax_price` | ❌ 不含客户费用，且非优惠后 |
| `accounts_receivable.receivable_money` | `real_money + customers_money` | ✅ |

**改造清单**（采购侧不变）：

| # | 文件 | 位置 | 改法 |
|---|---|---|---|
| 1 | `GoodsSales.php` | `examine()` 写 `writeoff_source` | `price = real_money + customers_money` |
| 2 | `GoodsSalesExchange.php` | `examine()` 写 `writeoff_source` | `price = -(real_money + customers_money)` |
| 3 | `Collection.php` | 前置超额校验 | `$all_money = real_money + customers_money` |
| 4 | `Collection.php` | 审核判满 | `more_money = (real_money+customers_money) - write_off - pay_money` |
| 5 | `Collection.php` | 反审核分支 | 同步 |
| 6 | `Writeoff.php` | 销售判满 | 同 #4 |
| 7 | `Writeoff.php` | 销售退货判满 | `(real_money+customers_money) + write_off - retreat_money` |
| 8 | `Writeoff.php` | 反审核分支 | 同步 |

- 前端 `writeoff.js` 的「单据金额」取 `writeoff_source.price`，改 #1/#2 后自动同步。
- **只对新业务生效**；历史 `pay_money/pay_status` 不回算。
- 开票基数仍是销货合计金额，客户费用不开票。

## 七、边界与异常

1. 只对账**已审核**单据；未审核、已删除、已结账期间的一律排除。
2. 一张单据只能进一张对账单：生成时校验 `recon_id=0`，编辑时排除已被占用的单据。
3. 一审通过即锁定；二审驳回/撤销才解锁。锁定期间编辑/删除/反审核/反对单均被拦截。
4. 撤销限制：已开票或已有收/退款时禁止撤销。
5. 删除对账单：仅待对账且未开票未收款；级联删快照/发票/日志，并清空单据 `recon_id/recon_code`。
6. 金额合计一律按**单据去重**（明细表里的单据级字段是重复值）。
7. 退货冲减：退货单各金额取负；对账单不得出现"负数量但正金额"的混算。
8. 孤儿数据：快照来自 `recon_doc` / `recon_info`，不实时 JOIN；「刷新明细」时源单不存在则提示并保留快照。
9. 发票超额默认拒绝；删除发票要求未收款。
10. 多张发票的台账写回是**全量重算**，保证删除发票后不留脏数据。
11. 收款口径统一（5.9）只对新业务生效，历史数据不回算。
12. 结账限制沿用 `Checkout::checkOutTime`。

## 八、验收清单

1. 工作台 7 项筛选正确；销货单与退货单同列展示，退货行数量/金额为负；合计为净额。
2. 勾选 3 家客户的多张单据 → 生成 3 张对账单，单号 `KHDZ...`，单据 `recon_id/recon_code` 回写，工作台不再显示。
3. 详情页与导出文件完全按模板版式：15 列、本期合计、各月未付款合计、总未付款、页脚声明；文件名 = 客户+期间。
4. 含退货的对账单：销货合计 = 销货 − 退货，客户费用同口径，总金额正确。
5. 财务「一审通过」→ 待二审、单据锁定；主管「二审通过」→ 已对账；「二审驳回」→ 回待对账、解锁、显示原因。
6. 「撤销对账」→ 解锁；改单后 `goods_sales_log` 有记录且详情可见；「刷新明细」金额更新。
7. 开票：连开 3 张 → 未开/部分/已开三态正确；删除一张 → 状态回退且「销货开票管理」同步。
8. 收款单核销 → 对账单部分收款/已收款；退货退款（retreat_money）使已收金额减少。
9. 含客户费用的单据：应收封顶、收款判满、核销判满、对账单总金额四处一致。
10. 非授权角色看不到按钮，直接访问 URL 被拦截。
