# 采购对账与付款申请 · 需求规格（2026-10-23）

> 参与角色：采购（发起对账 / 开票 / 付款申请）、财务（对账审核 / 付款初审）、审计（付款复审）、
> 领导（超阈值付款终审，可选）、出纳（打款 + 回单）。
> 本文是开发依据；实现细节以代码与迁移文件为准。

---

## 一、总体流程

```
仓库入库（已有）                       采购                                   财务
├ 采购单入库（可分批）                  ├ 新建对账单（勾选采购单，标记已对账）      │
├ 每次入库上传原始单据（已有）    ──→   ├ 上传对账单原始单据                      │
└ 入库记录可查看（已有）                ├ 提交财务审核  ───────────────────────→  审核对账单
                                        │                                           ├ 查看采购合同
                                        │                                           ├ 查看入库单 + 入库原始单据
                                        │                                           ├ 查看对账单附件
                                        │                                           └ 通过 / 驳回（填原因）
                                        │        ┌───────────── 通过 ───────────────┘
                                        ↓        ↓
                                  采购通知供应商开票
                                  上传发票（文件 + 发票号 + 金额 + 开票日期）
                                  新增账期记录（账期天数 → 到期日 = 上传日 + 天数）
                                        ↓ 到期前 N 天（设置项，默认 7）列表标黄 / 逾期标红
                                  采购发起付款申请
                                        ↓
                     财务审核 → 审计审核 →（金额 ≥ 阈值时）领导审核 → 出纳打款
                                                                        ├ 选账户/付款日期/流水号
                                                                        ├ 上传付款回单
                                                                        └ 自动生成付款单并核销应付
                     状态实时同步：采购界面、财务界面、出纳界面同一套数据
```

## 二、关键口径（已与需求方确认）

| 项 | 口径 |
|---|---|
| 对账单组织方式 | **供应商 + 对账期间**，一张对账单可勾选该供应商多张采购单 |
| 对账金额 | **按采购单整单金额**（`fa_kuerp_goods_purchase.real_money`，即优惠后价税合计），不看入库进度；部分入库的采购单也可纳入 |
| 对账单开票 | 一张对账单对应开票，**不按单张采购单拆分**；发票作为对账单附件上传 |
| 账期起算 | 从**发票上传日**起算，`到期日 = 上传日 + 账期天数` |
| 账期提醒 | `到期日 - 提醒天数 <= 今天` 且未付款 → 标黄提醒；`今天 > 到期日` → 标红逾期；提醒天数走设置项 |
| 付款落地 | 独立付款申请单做多级审批；出纳确认打款时**自动生成现有付款单**（`kuerp/payment`）并审核入账、核销采购单应付 |
| 审批链 | 固定 财务 → 审计 → 出纳；付款金额 ≥ 设置阈值时，在审计后插入「领导审核」节点 |

## 三、状态机

### 3.1 采购对账单 `fa_kuerp_purchase_recon`

| status | 名称 | 可执行操作 |
|---|---|---|
| 0 | 草稿 | 编辑 / 删除 / 提交财务审核 |
| 1 | 待财务审核 | 财务：审核通过 / 驳回 |
| 2 | 已审核（待开票） | 采购：上传发票、新增账期记录；开票后可发起付款申请 |
| 3 | 已驳回 | 采购：编辑后重新提交 |

独立状态字段：

- `invoice_status`：0 未开票 / 1 已开票
- `pay_status`：0 未付款 / 1 付款申请中 / 2 已付款

> 列表「业务状态」由三者组合展示：草稿、待财务审核、已驳回、待开票、待付款、付款审批中、已付款。

### 3.2 付款申请单 `fa_kuerp_purchase_payment_apply`

| status | 名称 | 流转 |
|---|---|---|
| 0 | 草稿 | 提交 → 1 |
| 1 | 待财务审核 | 通过 → 2；驳回 → 6 |
| 2 | 待审计审核 | 通过 → 金额≥阈值 ? 3 : 4；驳回 → 6 |
| 3 | 待领导审核 | 通过 → 4；驳回 → 6 |
| 4 | 待出纳付款 | 确认打款 → 5（生成付款单） |
| 5 | 已付款 | 终态 |
| 6 | 已驳回 | 采购可编辑后重新提交 → 1 |

`need_leader` 在提交时按 `purchase_payment_leader_money` 计算并固化，避免审批中途阈值变化导致流程跳变。

## 五、页面与功能

### 5.1 采购对账（菜单：采购 → 采购对账，`kuerp/purchase_recon`）

列表列：对账单号 / 供应商 / 对账期间 / 采购单数 / 对账金额 / 业务状态 / 开票状态 / 付款状态 / 付款到期日（含剩余天数，标黄标红） / 制单人 / 操作。

工具栏/行操作：

| 操作 | 条件 | 说明 |
|---|---|---|
| 新建对账单 | — | 供应商 + 对账期间 + 勾选采购单 |
| 编辑 | status ∈ {0,3} | 可增删采购单、改备注；移除的采购单解除 `recon_id` |
| 删除 | status ∈ {0,3} 且 pay_status=0 | 级联删明细、附件关系、日志 |
| 提交财务审核 | status ∈ {0,3} | 校验至少一张采购单、附件可留空 |
| 审核 | status=1 且有权限 | 财务弹窗：通过 / 驳回（必填原因） |
| 上传发票 | status=2 | 发票文件 + 发票号 + 金额 + 开票日期 + 账期天数 |
| 发起付款申请 | status=2 且已开票且未付款 | 跳付款申请新增页并带入本对账单 |

详情页（`detail`）分区：

1. 基本信息 + 金额汇总 + 状态
2. 采购单明细（单号 / 日期 / 数量 / 金额 / 入库状态）
3. **对账依据**（财务审核时重点看）：
   - 采购合同：供应商合同文件 + 关联采购订单的原始单据（逐单列出）
   - 入库单：每张采购单的每次入库记录（时间 / 数量 / 明细摘要）+ 该次入库的原始单据
   - 对账单：本对账单上传的附件（可继续上传 / 删除，type=8）
4. 发票与账期记录（发票号 / 金额 / 开票日期 / 账期天数 / 到期日 / 剩余天数）
5. 付款状态（关联付款申请单号、状态、付款日期）
6. 操作日志

### 5.2 付款申请（菜单：资金 → 付款申请，`kuerp/purchase_payment_apply`）

新增页：选供应商 → 列出「已审核 + 已开票 + 未付款」的对账单（可多选，同一供应商）→ 合计金额 → 保存草稿 / 提交审核。

详情页：申请信息 + 关联对账单明细 + 审批链时间线（财务 / 审计 / 领导 / 出纳）+ 付款回单 + 操作日志。

操作按钮按状态与权限显示：

- 编辑 / 删除 / 提交：status ∈ {0,6}
- 财务审核：status=1
- 审计审核：status=2
- 领导审核：status=3
- 确认打款：status=4（出纳；弹窗选账户、付款日期、流水号、上传回单）

### 5.3 出纳打款落账

在同一事务内：

1. 生成付款单 `fa_kuerp_payment`（单号前缀 FK）+ 付款账户行 `fa_kuerp_payment_account` +
   核销行 `fa_kuerp_payment_sale`（每张采购单一条，`business_type=4, type=1`）
2. 调用现有 `Payment::examine($paymentId, 1)` 完成账户扣款、供应商应付款减少、采购单 `pay_money/pay_status` 更新、台账写入
3. 付款回单存 `enclosure_log(type=10, order_id=申请单id)`
4. 回写申请单 `status=5 / payment_id / pay_*`，对账单 `pay_status=2`
5. 任一步失败整体回滚，提示原因

## 七、边界与异常

- 候选采购单：`purchase_type=1`、已审核、`recon_id=0`（编辑时含本单已选）；同一采购单不可出现在两张对账单。
- 对账后可反悔：仅草稿/驳回状态可移除采购单并清空 `recon_id`；已审核后不可改。
- 删除对账单：已进入付款申请（pay_status=1）或已付款（2）禁止删除。
- 付款申请金额：默认 = 所选对账单金额合计；出纳打款时按采购单 `real_money - pay_money` 封顶核销，
  若存在已付款的采购单导致可核销金额不足，明确报错并整体回滚。
- 已结账期间的采购单不允许纳入对账（沿用 `Checkout::checkOutTime`）。
- 附件删除沿用 `Enclosure::del()` 的「已关联业务单据不可删除」守卫；本模块删除附件需校验 type 归属。
- 所有金额/数量按系统 `price_decimal` / `number_decimal` 格式化。

## 八、验收清单

1. 采购新建对账单，勾选同供应商多张采购单 → 对账单生成，采购单 `recon_id` 回写，列表显示已对账。
2. 草稿可增删采购单；移除后采购单回到可对账状态。
3. 上传对账单附件后提交，财务详情页能看到：供应商合同、每张采购单的入库记录及入库原始单据、对账单附件。
4. 财务驳回 → 采购看到原因并可编辑重提；财务通过 → 状态变为待开票。
5. 上传发票 + 填写账期天数 → 到期日正确；到期前 N 天列表标黄、逾期标红（N 可在设置页改）。
6. 采购发起付款申请（可多张对账单）→ 财务 → 审计 →（超阈值）领导 → 出纳。
7. 出纳打款后：付款单生成并已审核、账户余额减少、供应商应付减少、采购单 `pay_money` 增加且 `pay_status` 正确、对账单已付款、申请单完成。
8. 各角色只能看到/操作自己权限内的按钮；非授权用户直接访问 URL 被拦截。

# 补充需求（2026-10-23 第二轮）

## 一、全供应商采购单列表（菜单：采购对账 → 采购单列表，`kuerp/purchase_recon/purchases`）

顶部筛选：日期区间、采购单号、供应商、对账状态（未对账/待财务审核/已审核/已驳回）、开票状态（未开票/已开票）、付款状态（未付款/付款申请中/已付款）。

列与状态标识：

| 列 | 口径 |
|---|---|
| 入库状态 | 未入库 / 部分入库 / 已入库（由 `kuerp_goods_purchase_info.storage_number` 汇总）**注：需求原文「是否已出库」，采购业务对应的是入库状态** |
| 对账状态 | 未对账 / 待财务审核 / 已审核 / 已驳回，并显示对账单号 |
| 开票状态 | 未开票 / 已开票（取所属对账单 `invoice_status`） |
| 付款状态 | 未付款 / 付款申请中 / 已付款（采购单 `pay_status`，由付款单核销更新） |
| 已付金额 | 采购单 `pay_money` |

行操作：已对账的采购单可直接打「查看对账单」跳到对账单详情。

## 二、供应商待付款统计（菜单：采购对账 → 供应商待付款统计，`kuerp/purchase_recon/supplierstat`）

顶部筛选：日期区间、供应商。按供应商汇总：

采购单数、采购额合计、已对账金额、未对账金额、已开票金额、待开票金额、已付款金额、**待付款金额（采购额 - 已付款）**、逾期金额（已开票且未付款、账期到期日 < 今天）。
页面顶部同时显示全部筛选结果的合计（采购额/已对账/未对账/已开票/待开票/已付款/待付款/逾期）。按待付款金额倒序。

## 三、审核/付款页内嵌原始单据

财务审核弹窗（`purchase_recon/audit`）与付款申请页面（新增/编辑/详情）按对账单展示资料，资料均为**业务人员上传的原始单据**，不是系统生成的打印件：

1. 对账单文件（`enclosure_log.type=8`）
2. 采购合同：供应商合同（`kuerp_suppliers.contract`）+ 关联采购订单的原始单据（`type=1`）
3. 入库单：每张采购单的**历次入库记录**及该次入库的原始单据（`type=7`）
4. 发票（`type=9`，付款申请页面及详情展示）

实现：

- 资料装配集中在 `app\admin\model\kuerp\PurchaseRecon::materials($reconIds)`（批量查询，返回按对账单ID索引的数组）；
- 财务审核弹窗服务端渲染；付款申请详情服务端渲染；付款申请新增/编辑页每行「资料」按钮 AJAX（`purchase_recon/materials`）展开；
- 付款申请新增页的「资料」可随时查看，不影响勾选/金额合计。

## 四、本次补强的一致性守卫

- 已纳入对账的采购单：**禁止编辑、删除、反审核**（`GoodsPurchase::edit/del/_examine`），避免对账金额与票据被改坏。
- 由付款申请生成的付款单：**禁止在「资金 → 付款单」中反审核**（`Payment::examine` 反审核分支校验 `purchase_payment_apply.payment_id`），防止账户/应付/对账单状态不同步。

## 五、仍待完善的点（建议后续迭代）

1. **发票金额校验**：目前允许发票金额与对账金额不一致（只做展示），可增加「差异提示/必须相等」策略。
2. **部分开票**：一张对账单多张发票时，付款申请仍按对账金额全额申请；如需按发票金额付款，需要把付款申请明细改到发票级。
3. **付款撤销/反审核**：付款单反审核被禁止后，打错款只能线下冲正；可增加「付款申请撤销（红冲）」流程。
4. **账户余额校验**：出纳打款未校验账户余额是否充足（现有付款单逻辑允许负余额）。
5. **审核人互斥**：未限制「申请人不能审核自己的单据」，如需要可按角色/人员加规则。
6. **权限分配**：新增菜单/规则的默认角色勾选需管理员在「角色管理」中完成（采购/财务/审计/领导/出纳）。
7. **首页提醒**：账期到期提醒目前只在采购对账列表标色，如需可在数据面板增加待办卡片。

> `goods_purchase.real_money` 为准（`real_money = Σ money_tax_price − preferential_money`，
> 即价税合计减优惠），付款单核销/供应商应付也用它。本规格按代码现状统一为 **real_money**。

## 6.2 采购对账目标状态机（对齐后）

```
采购单/退货单：recon_status 0未对账 → 1已锁定(一审通过) → 2已对账(二审通过)
对账单 status：0 待对账（草稿/驳回） → 1 待二审（财务一审通过） → 2 已对账（二审通过）
                ↑                                            │
                └────────── 二审驳回 / 撤销对账 ──────────────┘
invoice_status：0 未开票 / 1 部分开票 / 2 已开票（按累计开票金额派生）
pay_status：    0 未付款 / 1 部分付款 / 2 已付款（按采购单 pay_money − 退货单 retreat_money 派生）
```

- 一审通过即锁定所含采购单/退货单；二审驳回或撤销对账解锁。
- 驳回必须填原因；驳回回到 0 并在列表显示「已驳回·待重提」。
- 对账净额 ≤ 0 时：允许生成对账单（用于核销退货），但**不允许发起付款申请**。

## 6.6 已落地（2026-10-27）

按用户确认的「二审 + 发票不写回采购开票台账 + 需要导出/打印模板（无物流单号）」实施：

- **退货冲减**：`fa_kuerp_goods_exchange` 增加 `recon_id/recon_code/recon_status`；
  对账明细增加 `doc_type`（1采购单/2退货单），退货行数量、金额为负；主表增加 `return_count`，`total_money` 为净额。
- **二审**：状态机改为 `0待对账 / 1待财务审核 / 2待二审 / 3已对账 / 4已驳回`；
  财务一审通过锁定单据（`recon_status=1`），二审通过置 `recon_status=2`，
  二审驳回或撤销对账解锁（`recon_status=0`）。新增权限 `secondaudit`、`revoke`。
- **多张发票/部分开票**：`invoice_status` 0未开票/1部分开票/2已开票，主表 `invoice_amount` 累计；
  发票号在同一对账单内唯一，开票金额不得超过剩余可开票金额（净额）。
- **锁定**：采购单、购货退货单的编辑/删除/反审核/对单反对单均在 `recon_status≠0` 时禁止。
- **付款申请**：候选对账单要求 `status=已对账` + `invoice_status=已开票` + `pay_status=0` + 净额>0；
  出纳打款按对账单净额分摊到所含采购单核销（退货单已在退货审核时冲减应付，不重复核销）。
- **导出/打印**：新增 `kuerp/purchase_recon/export`（xlsx）与 `printpage`（HTML 打印）；
  版式对齐客户对账模板 14 列，**去掉物流单号**，含本期合计、往期各月未付款合计、总未付款与页脚声明；
  文件名：`供应商名称 + 对账期间`。
- **仍不在本期范围**：发票写回 `kuerp_invoicing`（默认不写回，按确认意见）；退货红字发票与销货侧同一遗留问题。
